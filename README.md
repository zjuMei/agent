# 最简旅行智能体

参照 [Hello-Agents 第 1.3 节](https://github.com/datawhalechina/hello-agents/blob/main/docs/chapter1/第一章%20初识智能体.md)，用一个 Python 脚本实现：模型选择行动 → 调用天气或搜索工具 → 将结果交给模型 → 输出最终建议。最多运行 6 轮；最后一轮只生成最终回答，不再执行工具。

## 运行

需要 Python 3.9+ 和一个兼容 Chat Completions 的模型服务。搜索景点时还需要 [Tavily](https://www.tavily.com/) API Key。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

在 `.env` 中填入模型 API Key、API 基础地址、模型名称，以及搜索景点所需的 Tavily API Key。`LLM_API_KEY` 和 `LLM_MODEL` 必填；`LLM_BASE_URL` 留空时使用 SDK 默认地址。只查询天气无需填写 `TAVILY_API_KEY`。密钥只放在本地 `.env`，不要提交。

```bash
python agent.py "上海现在的天气怎么样？"
python agent.py "查询今天上海的天气，并推荐一个适合游玩的景点。"
```

只问天气时查询后直接回答，明确需要景点推荐时才搜索景点。
天气工具为 `get_weather(city="杭州", mode="today")`：默认读取今日最高/最低温和分时天气、降雨预报；问“现在天气”时用 `mode="current"` 读取当前观测。观测时间优先读取 `localObsDateTime`，缺失时读取 `observation_time`；后者保留接口原始时间并提示时区未标注，不当作北京时间。今日按用户的上海时区匹配日期，不将可能过期的观测日期当作今天；接口缺少对应日期的预报时明确报错，不替换成其他日期。海外城市也按用户上海时区选日期，输出会明确日期及这一依据，分时预报保留接口时间。全天预报与当前观测分别标注，缺失数据不会补造。
景点搜索通过 `requirements` 参数接收本次限制（例如“仅限室内”），优先于长期偏好。工具调用保持单行，最终答案支持多行，并兼容 `Action: Finish[...]` 和直接返回的 `Finish[...]`。空输出或缺少 Action 时返回明确的格式提示，不进入工具解析。
景点工具为 `get_attraction(city="杭州", requirements="", query="")`，不再接收未使用的 `weather` 参数。可选的 requirements、query 允许为空；城市和偏好字段必须非空。缺少必填参数、未知参数、参数类型及语法错误会具体反馈，网络失败和接口返回结构异常分别提示。
搜索使用简短关键词，不将执行规则、偏好 JSON 或详细天气拼入查询。未指定 `query` 时，用城市、景点主题和本次要求生成搜索词；没有本次要求时再加入长期兴趣。预算、出行偏好和天气仍在模型上下文中用于筛选。关闭 Tavily 自动摘要，仅返回搜索结果及来源，Observation 会显示实际搜索词、结果数量和每条结果的标题、摘要、来源；单条摘要最多保留 1000 字符。正常的空结果与 results 字段缺失或异常分别处理。提示词要求模型发现空结果或无关结果时，通过可选 `query` 参数最多改写重搜一次；仍无可靠结果时说明失败，不编造推荐。
默认推荐 3 个选择，每个附理由及对应来源；用户指定数量时遵循要求，可靠结果不足时少推荐并说明。提示词要求合并重叠地点、结合日期筛选季节性描述、严格遵守本次限制，不把未经核实的票价、开放时间或预约规则作为确定事实。这些内容判断仍依赖模型遵循提示词。
每轮模型会收到当前轮次和剩余轮次提醒。格式错误与重试都计入 6 轮上限，最后一轮要求用 Finish 总结可靠信息及未完成部分。若模型仍未结束或调用失败，程序报告成功执行的工具及失败原因。

## 自动记忆

模型识别到用户明确表达的长期兴趣、常用预算或出行偏好时，会按提示词自动选择 `save_preferences` 工具，不需要用户说“记住”。工具将偏好保存在脚本旁的 `preferences.json`，下次运行时自动读取，景点搜索也会使用这些偏好。更新一个字段时保留其他字段；本次临时要求不长期保存，本次请求优先于历史偏好。内容未变化时不重复写文件，保存或未变化的 Observation 都返回完整最新偏好；空调用会明确提示至少提供一个有效字段。

```bash
python agent.py "我平时喜欢历史文化景点，通常乘公共交通。查询北京天气并推荐一个景点。"
python agent.py "查询上海天气并推荐一个景点。"
```

第一条请求中的偏好由模型提取并保存，第二次运行会带上已有偏好。首次保存成功时才创建文件；所有运行共用同一份单用户偏好。记忆提取依赖模型遵循提示词，保存也占用 6 轮行动额度。

直接运行 `python agent.py` 会使用北京的示例问题。终端按教程格式显示用户输入、循环轮次、模型调用状态、模型返回的 Thought 行动摘要和 Action、工具返回的 Observation，以及最终答案。天气来自 wttr.in 的当前观测或今日预报，景点信息来自 Tavily 搜索；真实运行需要能访问这些服务。
